# Personal runtime

The default runnable application command is the explicit synthetic demo launcher documented at the repository root. Directly executing `src/main.ts` requires `PWACLOUD_MODE=demo` or `PWACLOUD_MODE=chatgpt-plan-local`. Startup never chooses an undocumented provider or a paid fallback.

`createRuntime(config)` returns `{app, listen, close, registerInstallation, provider, database}`. Production callers pass an explicit database path, exact application origin, operator trust roots and trusted guest preparation. The direct registration method accepts an already verified package and is an internal integration seam; the HTTP install route independently verifies all archive, envelope and receipt bytes.

The HTTP default is `127.0.0.1:4173`. Its synthetic demo uses an explicitly labeled `pwacloud-demo-session` HttpOnly cookie so Chromium and WebKit can exercise the loopback development build. Personal mode uses `__Host-pwacloud-session`, Secure, HttpOnly, Path=/, SameSite=Strict. State changes require the exact Origin and `x-csrf-token`; null and cross-site origins are rejected. Tokens never reach the shell.

Phone pairing requires a configured TLS listener and an HTTPS origin. Set `PWACLOUD_TLS_CERT`, `PWACLOUD_TLS_KEY` and `PWACLOUD_ORIGIN` to the certificate, private key and exact trusted origin under the operator's control. A configured HTTPS string without a TLS listener is rejected. The host computer confirms the selected account generation before issuing a random invitation; codes expire after two minutes, are stored as hashes, consumed once and rate limited. Test certificates verify the implementation's TLS boundary; they do not establish a phone's trust or count as physical-device acceptance.

Personal mode uses a stable host ID and PWACloud's own protected credentials under `PWACLOUD_DATA_DIRECTORY` (default `~/.pwacloud`). Windows uses DPAPI CurrentUser encryption; Unix requires a separate owner-only 32-byte credential key through `PWACLOUD_CREDENTIAL_KEY_FILE`. A process lock prevents two main runtime processes from racing rotating credentials. No existing Codex, ChatGPT or other application's credentials are read.

Continue with ChatGPT explicitly starts a separate HTTP callback listener on `127.0.0.1` before returning the official authorization URL. Only its port varies; the path is `/auth/callback`. The flow uses state, nonce and PKCE S256; the callback's issued client ID and jose-verified issuer/audience/subject bind the registration. Identity scopes alone leave inference unavailable. Account switching invalidates old app sessions, pairings and grants. The selected registration and durable run metadata contain no OAuth tokens.

The real provider source follows the [official local registration flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in) and [documented models and inference transport](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference), checked October 1, 2026. The adapter uses only the public model and Responses endpoints, preserves visible model slugs, and emits `store:false` and `stream:true` without unsupported generation fields. Local output and elapsed limits stop delivery rather than promising provider credit refunds.

Runs are admitted and journaled in SQLite before provider dispatch. Idempotency keys bind the workspace, installation and exact request; conflicting reuse is rejected. SSE reconnect replays sequenced stored events, never starts another inference. The runtime records interrupted work after restart and requires explicit new submission. Revocation, sign-out, cancellation, time and output limits stop delivery while retaining admitted usage.

Account admission keys derive from the verified issuer and subject, independently of the registration client ID and session generation. Selecting or reconnecting the same account cannot reset the durable hourly counter. Legacy rows without a verified identity key conservatively count toward account admission until they age out. The last SSE subscriber disconnect starts a five-second grace interval (`disconnectGraceMs` in embedded runtime configuration); reconnecting clears it, and expiry cancels unfinished inference without refunding its admitted usage. Completed and cancelled journals remain available for authorized replay.

Signed package approval posts `packet`, `grants` and `expectedGeneration` to `/v1/installs`. First registration accepts an omitted generation or zero; an existing registration requires its exact current generation. The authenticated `/v1/installs/:id/registration` endpoint returns the generation, state, digest and current permission IDs, including uninstall tombstones. The comparison, installed pointer and grants are committed in one transaction after asynchronous verification and guest preparation. A stale approval receives HTTP 409 and cannot restore revoked consent or reuse an old installation generation.

Removal requires `DELETE /v1/installs/:id` with the JSON body `{ "expectedGeneration": currentGeneration }`. Missing or stale generations are rejected; an expired verification receipt does not prevent an authenticated owner from removing the installation. Removal atomically drops grants and advances its durable tombstone. Personal-mode public trust excludes synthetic demo authority and validates that every exposed key contains public material only.

Public reference releases require verified archive signatures, envelope signatures and provenance from the exact repository, release tag and `.github/workflows/plugin-release.yml` identity. The runtime obtains Sigstore trust through the [official TUF client](https://github.com/sigstore/sigstore-js/tree/main/packages/tuf) and issues a one-day local verification receipt only after those checks pass. Its signing key is independently generated and protected locally; it attests the verified publisher evidence and never claims to be that publisher's private key. The authenticated `/v1/trust` endpoint exposes public roots to the trusted shell. Package input cannot add a trust root. Restarts retain the same local authority, and receipt expiry is rechecked on capability use.

Real eligible-account completion, real cancellation and physical phone pairing remain external tests. Connected third-party plugin scope needs the applicable written authorization before real plugin inference. The main program does not provide an environment flag that bypasses that gate. Hosted and VM credential modes remain disabled.
